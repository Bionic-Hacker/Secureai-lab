================================================================================
SecureAI Lab — Phase 5 Walkthrough (Secure Code Review Engine)
Garuda Linux / fish shell command reference
================================================================================
What Phase 5 adds:
  - Bandit (Python) + a custom Semgrep ruleset (Python/JS/TS) for SAST
  - CVSS 3.1 scoring via a curated category mapping (not computed per-CVE —
    see the walkthrough's note on why EPSS was deliberately dropped)
  - Findings scoped to Phase 2's existing permission model — no new
    upload path, this scans documents already uploaded
  - Runs fully offline at scan time — the Semgrep ruleset is bundled into
    the image at build time, no registry call needed at runtime

STEP 6 — Create a deliberately vulnerable test file
--------------------------------------------------------------------------------
This file has real, intentional issues across several categories so you
can confirm the scanner actually catches something, not just that it
runs without error:

    printf '%s\n' \
'import subprocess' \
'import pickle' \
'' \
'def get_user(conn, username):' \
'    query = f"SELECT * FROM users WHERE username = {username}"' \
'    return conn.execute(query)' \
'' \
'def run_backup(target_dir):' \
'    subprocess.call("tar -cf backup.tar " + target_dir, shell=True)' \
'' \
'def load_session(data):' \
'    return pickle.loads(data)' \
'' \
'API_KEY = "sk-fake-example-key-for-testing-do-not-use"' \
> /tmp/vulnerable_test.py

    command cat /tmp/vulnerable_test.py

--------------------------------------------------------------------------------
STEP 7 — Upload it and trigger a scan
--------------------------------------------------------------------------------
    set TOKEN (curl -s -X POST http://localhost:8080/api/v1/auth/login \
      -H "Content-Type: application/json" \
      -d '{"email":"bionichacker2@test.com","password":"Florida2027!"}' \
      | grep -o '"access_token":"[^"]*' | cut -d'"' -f4)

    curl -s -X POST http://localhost:8080/api/v1/documents \
      -H "Authorization: Bearer $TOKEN" \
      -F "file=@/tmp/vulnerable_test.py;type=text/plain"

Note the "id" field, then trigger a scan on it:

    set DOC_ID "paste-the-id-here"
    curl -s -X POST http://localhost:8080/api/v1/code-review/scan/$DOC_ID \
      -H "Authorization: Bearer $TOKEN"

--------------------------------------------------------------------------------
STEP 8 — Retrieve findings
--------------------------------------------------------------------------------
    sleep 5
    curl -s http://localhost:8080/api/v1/code-review/findings/$DOC_ID \
      -H "Authorization: Bearer $TOKEN"

Expect "code_scan_status":"completed" and multiple findings — at minimum
Bandit should flag the f-string SQL query, the shell=True subprocess
call, and pickle.loads(); the summary object should show non-zero counts
across critical/high severities. If it still says "scanning", wait a few
more seconds and check again.

--------------------------------------------------------------------------------
STEP 9 — Confirm permission isolation still holds
--------------------------------------------------------------------------------
Code review reuses Phase 2's permission model entirely — worth a quick
confirmation it actually carried over correctly:

    curl -s -X POST http://localhost:8080/api/v1/auth/register \
      -H "Content-Type: application/json" \
      -d '{"email":"scan-test-user@test.com","display_name":"ScanTest","password":"AnotherStr0ng!Pass9"}'

    set TOKEN2 (curl -s -X POST http://localhost:8080/api/v1/auth/login \
      -H "Content-Type: application/json" \
      -d '{"email":"scan-test-user@test.com","password":"AnotherStr0ng!Pass9"}' \
      | grep -o '"access_token":"[^"]*' | cut -d'"' -f4)

    curl -s http://localhost:8080/api/v1/code-review/findings/$DOC_ID \
      -H "Authorization: Bearer $TOKEN2"

Expect a 404 — the second user has no access to the first user's
document, so findings for it should be completely invisible, same as
every other document-scoped endpoint in this project.
