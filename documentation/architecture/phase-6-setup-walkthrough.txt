SecureAI Lab — Phase 6 Walkthrough (Threat Modeling Module)
Garuda Linux / fish shell command reference
================================================================================
What Phase 6 adds:
  - Structured threat models: a title + system description, containing
    individually STRIDE-categorized threat entries
  - AI-assisted generation using Phase 4's chat provider — feed it a
    system description, get a draft STRIDE analysis back
  - Defensive JSON parsing: if the local model's output can't be parsed
    as structured data, nothing is silently dropped — a single
    human-reviewable entry is created containing the raw output instead
  - Full manual CRUD — every AI-generated entry can be edited or
    overridden, and a threat model isn't "reviewed" until a human
    explicitly marks it so
  - A seed script populating a REAL threat model for this project's own
    RAG cross-tenant isolation — the platform reviewing itself

STEP 7 — Test AI-assisted generation on a genuinely new threat model
--------------------------------------------------------------------------------
This is the real test of the local-model integration — expect it to take
a while on first use if the model isn't already loaded in memory from an
earlier assistant conversation:

    curl -s -X POST http://localhost:8080/api/v1/threat-models \
      -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
      -d '{"title":"Test: File Download Endpoint","system_description":"An API endpoint lets authenticated users download a file by ID. The file path is looked up from a database record and served from local disk.","generate_with_ai":true}'

Expect a 201 with a populated "entries" array, "ai_generated":true on
each one. If the local model's output couldn't be parsed as JSON,
you'll instead see exactly one entry whose threat_description begins
with "AI generation produced a response that couldn't be parsed..." —
that's the defensive fallback working as designed, not a crash. Either
way, note the returned "id".

--------------------------------------------------------------------------------
STEP 8 — Exercise the human-review workflow
--------------------------------------------------------------------------------
Edit one AI-generated entry manually (replace ENTRY_ID with one from the
response above):

    set ENTRY_ID "paste-an-entry-id-here"
    curl -s -X PATCH http://localhost:8080/api/v1/threat-models/$TM_ID/entries/$ENTRY_ID \
      -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
      -d '{"mitigation_status":"mitigated"}'

Confirm "human_edited":true is now set. Then mark the whole model
reviewed:

    curl -s -X POST http://localhost:8080/api/v1/threat-models/$TM_ID/review \
      -H "Authorization: Bearer $TOKEN"

Confirm "status":"reviewed" and "reviewed_by" now shows your user ID.
